# 📵 디지털 웰빙 타이머

스마트폰 과의존을 예방하는 웹 앱. 목표 시간을 정해 타이머를 돌리는 동안 폰을
멀리하고, 성공 기록을 반 친구들과 공유하며 서로 응원한다.

**사이트 주소**: https://neomeka4725.github.io/timer-app/

---

## 처음 참여하는 사람에게

이 문서를 먼저 읽어주세요. **모르고 어기면 사이트가 조용히 망가지는 규칙**이
두 개 있습니다 (아래 "꼭 지킬 것" 참고).

### 어떤 프로젝트인가

- 프레임워크 없이 **순수 HTML / CSS / JavaScript**로만 만든다 (React, Vue 등 사용 금지)
- GitHub Pages로 무료 배포한다. **서버가 없다**
- 반 친구들 기기가 아이폰·아이패드·갤럭시로 섞여 있어서 웹 앱으로 만든다.
  Swift 같은 특정 OS 전용 앱은 만들지 않는다
- 회원가입·로그인이 없다. **닉네임 + 숫자 4자리**만 입력해서 쓴다

> **목표 시간 상한(120분)은 두 곳에 있다.** `script.js` 의 `MAX_MINUTES` 와
> `firestore.rules` 의 `goalMinutes <= 120`. 하나만 고치면 기록이 조용히
> 거부된다. 반드시 같이 고칠 것.

### 아이패드에서 조심할 것

화면을 반으로 나눠 쓰면(Split View) 두 앱이 같이 보여서 **화면 이탈 감지가
안 된다.** 옆에서 유튜브를 틀어도 이 앱은 모른다. 창 너비가 기기 화면보다
뚜렷하게 좁은지로 짐작해서 막고 있는데(`splitViewInfo()` in `script.js`),
브라우저에 정확한 기능이 없어서 짐작이다. 실제 기기에서 확인이 필요하다.

**다른 앱에서 나는 소리는 감지할 수 없다.** 배경 유튜브를 막거나, 유튜브와
음악을 구분하는 것은 웹에서 불가능하다. 제안하기 전에 이 점을 기억할 것.

### 웹 앱의 한계 (제안하기 전에 확인할 것)

웹 앱은 **다른 앱을 강제로 차단할 수 없다.** 그래서 "강제 차단" 기능은 만들 수
없고, 스스로 하는 약속 + 기록 공유를 통한 동기부여 방식으로 설계한다.

## 파일 구조

| 파일 | 하는 일 |
|---|---|
| `index.html` | 화면 6개의 구조 (닉네임 / 설정 / 타이머 / 내 기록 / 게시판 / 순위표) |
| `style.css` | 디자인 |
| `script.js` | 화면 전환, 타이머, 소리, 각 화면 그리기 |
| `storage.js` | 이 기기 안에 기록·닉네임·설정 저장 (localStorage) |
| `cloud.js` | Firebase와 통신 (기록 동기화, 게시판, 응원, 순위, 닉네임 확인) |
| `manifest.json` | 홈 화면에 추가했을 때 앱처럼 보이게 하는 설정 |
| `icon-192.png`, `icon-512.png` | 앱 아이콘 |
| `변경기록.md` | 무엇을 왜 바꿨는지 |
| `firestore.rules` | Firebase 보안 규칙 원본 (콘솔에 붙여넣는 것) |

화면은 전부 `index.html` 안에 있고, `hidden` 클래스를 붙였다 뗐다 하며
하나씩 보여준다. `script.js`의 `showScreen()`이 그 일을 한다.

## ⚠️ 꼭 지킬 것 두 가지

### 1. 파일을 고치면 `index.html`의 버전 번호를 올린다

`index.html` 맨 위와 맨 아래에 이렇게 되어 있다.

```html
<link rel="stylesheet" href="style.css?v=34" />
<script src="storage.js?v=34"></script>
<script src="cloud.js?v=34"></script>
<script src="script.js?v=34"></script>
```

`?v=34`는 브라우저가 옛날 파일을 계속 쓰지 않게 하는 표시다.
**CSS나 JS를 고쳤으면 이 숫자를 전부 같은 값으로 하나 올려야 한다** (`?v=35`).

안 올리면 어떻게 되나: 사파리가 예전 `script.js`를 그대로 쓴다. 새 버튼은
화면에 보이는데 눌러도 아무 반응이 없다. 원인을 찾기 매우 어렵다.
(실제로 한 번 겪었다.)

### 2. Firebase에 새 데이터를 저장하려면 보안 규칙부터 고친다

Firebase는 **규칙에 허용한다고 적어둔 것만** 저장된다. 새로운 종류의 데이터를
저장하는 코드를 짜면, 코드가 아무리 맞아도 `403 Missing or insufficient
permissions` 오류가 나며 조용히 실패한다.

새 필드나 새 컬렉션을 추가할 때는 **Firebase 콘솔 → Firestore Database →
규칙** 에서 규칙을 먼저 고치고 "게시"를 눌러야 한다.

## Firebase 데이터 구조

프로젝트 ID는 `timer-app-6965c`, 무료(Spark) 요금제다.

Firebase 라이브러리를 받지 않고 **Firestore REST API를 `fetch`로 직접**
호출한다 (`cloud.js`). 외부 파일을 안 받으니 사이트가 가볍고, 순수 JS
원칙에도 맞는다. 실시간 동기화는 하지 않고 화면을 열 때 조회한다.

### `records_v2` — 타이머 기록 (내 기록 + 순위표에 사용)

| 필드 | 종류 | 설명 |
|---|---|---|
| `nickname` | 문자 (1~8자) | 누구 기록인지 |
| `goalMinutes` | 숫자 (1~600) | 목표 시간(분) |
| `elapsedSeconds` | 숫자 (0~36000) | 실제로 버틴 시간(초) |
| `result` | 문자 | `success` / `left`(화면 이탈) / `gaveup`(포기) |
| `at` | 시각 | 언제 |

### `posts_v2` — 게시판 글

`nickname`, `goalMinutes`, `elapsedSeconds`, `message`(100자까지), `at`

### `posts_v2/{글번호}/cheers` — 응원

`nickname`, `emoji`(8자까지), `message`(30자까지), `at`

### `users/{닉네임}` — 닉네임 주인 확인용

| 필드 | 종류 | 설명 |
|---|---|---|
| `pinHash` | 문자 (64자) | 숫자 4자리를 SHA-256으로 바꾼 값 |
| `at` | 시각 | 언제 등록했는지 |

만들기만 되고 **고치거나 지울 수 없다.** 그래서 비밀번호를 바꿀 수 없다.
(아래 "친구가 비밀번호를 잊었을 때" 참고)

> 보관함 이름 끝에 `_v2`가 붙어 있는 이유: 개발 중 쌓인 시험용 기록을 버리려고
> 이름을 바꿨다. 옛 `records` / `posts`는 보안 규칙에서 빠져 있어 아무도
> 읽거나 쓸 수 없다.

### `activeChallenges/{닉네임}` — 지금 집중 중인 사람

| 필드 | 종류 | 설명 |
|---|---|---|
| `nickname` | 문자 | 누구인지 |
| `mission` | 문자 (20자까지) | 이번 판에 뭘 하는지. 비어 있을 수 있다 |
| `goalMinutes` | 정수 | 목표 시간 |
| `startedAt` | 시각 | 시작한 때 |
| `endAt` | 시각 | 끝나는 때 |

문서 번호를 **닉네임**으로 쓴다. 그래야 한 사람이 여러 개 올라가지 않는다.
타이머를 시작하면 만들고, 성공·실패·포기·화면 이탈 때 지운다.

**이 보관함만 지우기(delete)를 허용해야 한다.** 앱을 그냥 닫아버리면 문서가
남는데, 그러면 계속 집중 중인 것처럼 보이기 때문이다. 지우기가 막혀 있어도
`endAt`이 지난 것은 목록에서 빼므로 큰 문제는 없지만, 찌꺼기가 쌓인다.

### `challengeCheers` — 도전자에게 보내는 응원

`challengeId`(닉네임|시작시각), `from`(보낸 사람), `at`(시각)

숫자를 하나 두고 올리는 대신 **문서를 하나씩 쌓아서 센다.** 숫자를 고치려면
수정 권한이 필요한데, 그걸 열면 아무나 남의 기록을 고칠 수 있게 된다.
게시판 응원과 같은 방식이다.

> **읽기 횟수를 아껴야 한다.** 무료 요금제는 하루 5만 번 읽을 수 있다.
> 순위표는 기록 전체(최대 2000개)를 읽는 비싼 질의라 1분간 담아뒀다가
> 다시 쓴다 (`cloud.js`의 `rankingCache`). 도전 중 목록의 티어 배지도
> 같은 자료를 쓴다.
> 새 기능을 넣을 때 화면을 열 때마다 전체를 읽지 않는지 확인할 것.

> **첫 화면 티어는 인터넷을 안 본다.** 토큰 수를 이 기기에 적어두고
> (`storage.js` 의 `wellness-timer-tokens`) 그걸 바로 그린다. 판이 성공하면
> 목표 분을 더하고, 내 기록 화면을 열 때 진짜 값으로 맞춘다.
> **첫 화면에 뭔가를 더 띄우고 싶을 때 `collectRecords()` 를 부르지 말 것.**
> 앱을 열 때마다 기록 전체를 읽게 되어 읽기 0회짜리 동작이 40회가 된다.

> **오류를 던질 때는 반드시 `makeError(메시지, res.status)` 를 쓸 것.**
> 그냥 `new Error` 로 던지면 상태 코드가 사라져서, 403(보안 규칙이 막음)과
> 진짜 연결 실패를 구분할 수 없다. 그러면 인터넷이 멀쩡한 사람에게
> "인터넷을 확인하세요"라고 잘못 안내하게 된다. 실제로 두 번 겪은 문제다.

### 보안 규칙

전체 규칙은 **[`firestore.rules`](firestore.rules)** 에 있다. 이 파일이 실제로
콘솔에 올라가 있는 내용과 같아야 한다. 새 보관함을 쓰는 기능을 만들면
**이 파일도 같이 고치고 콘솔에 다시 올릴 것.**

올리는 법: Firebase 콘솔 → Firestore Database → 규칙 → 있는 내용을 전부
지우고 `firestore.rules` 를 통째로 붙여넣기 → 게시.

#### 요약

- **읽기는 누구나** — 로그인이 없으니 서로 기록을 봐야 한다
- **쓰기는 형식이 맞을 때만** — 필드 이름·종류·길이가 위 표와 정확히 같아야 한다.
  적혀 있지 않은 필드가 하나라도 섞이면 거부된다
- **수정은 아무도 못 한다** — 남의 기록을 고칠 수 없다
- **삭제는 `activeChallenges`만 된다** — 도전이 끝나면 지워야 하기 때문이다.
  나머지는 지울 수 없고, 지워야 할 게 있으면 주인이 콘솔에서 직접 지운다
- 테스트 모드가 아니라서 **30일 뒤 잠기지 않는다**

`apiKey`가 `cloud.js`에 그대로 적혀 있는데 **이건 정상이다.** 웹 Firebase는
이 값이 공개되는 구조이고, 실제 보안은 위의 규칙이 담당한다. 숨기려 하지 말 것.

## AI 도구(ChatGPT 등)로 작업할 때

AI는 이 프로젝트를 모른다. 그냥 "타이머 앱 만들어줘" 하면 React를 쓰거나
Firebase 라이브러리를 불러오는 코드를 주는데, 둘 다 우리 규칙에 어긋난다.
이미 만들어 둔 기능을 처음부터 다시 만들기도 한다.

👉 **[AI-프롬프트.md](AI-프롬프트.md) 를 열어서, 그 안의 글을 대화 시작할 때
붙여넣어라.** 프로젝트 규칙, 파일 구성, 이미 완성된 기능, 데이터 구조,
주요 함수가 정리되어 있다.

붙여넣은 다음, **고치려는 파일의 내용을 통째로 복사해서 같이 준다.**
AI는 GitHub을 볼 수 없으므로 파일을 안 주면 짐작으로 답한다.

같은 문서 아래쪽에 티어·연속 학습·주간 순위처럼 지금 만들려는 기능마다
**미리 알아야 할 함정**도 정리해 두었다.

### 받은 코드를 반영하는 방법

1. `github.com/neomeka4725/timer-app` 에서 고칠 파일을 연다
2. 연필(✏️) 아이콘을 누른다
3. 고친다
4. 아래 **Commit changes** 를 누른다
5. `?v=` 번호를 올려야 하면 `index.html`도 같은 방법으로 고친다
6. 1~2분 뒤 사이트에서 확인한다

## 같이 작업하는 방법

### 배포 흐름

`main` 브랜치에 들어간 내용이 곧 사이트다. `main`에 합쳐지면 1~2분 뒤
자동으로 반영된다.

1. 작업용 브랜치를 만들어 거기서 고친다 (`main`에 바로 올리지 않는다)
2. Pull request를 만든다
3. 상대방이 한 번 보고 merge 한다

### 충돌을 줄이려면

- **같은 파일을 동시에 고치지 않는다.** 누가 어느 파일을 맡을지 먼저 정할 것
- 고치기 전에 항상 최신 `main`을 받아온다
- 기능 하나가 끝날 때마다 바로 merge 한다. 오래 묵힐수록 충돌이 커진다

### 고친 뒤 확인할 것

서버가 필요 없으므로 `index.html`을 브라우저로 열면 바로 확인된다.
단, Firebase 기능(게시판·순위표)은 파일을 직접 열면 막힐 수 있으니
GitHub Pages에 올린 뒤 확인하는 편이 확실하다.

확인 목록:

- [ ] 타이머 시작 → 카운트다운 → 성공
- [ ] 타이머 중 다른 탭으로 30초 넘게 나갔다 오면 실패 처리
- [ ] 30초 안에 돌아오면 3번까지 봐주고, 그동안 남은 시간이 안 줄어드는지
- [ ] 쉬었다 하기를 켜면 5분 쉬는 시간이 붙는지 (쉬는 중엔 나가도 실패 아님)
- [ ] 오래 나갔다 와도 실패로 남는지 (없던 일로 사라지면 안 된다)
- [ ] 패드에서 두 칸으로 보이는지, 화면을 나누면 폰 배치로 돌아오는지
- [ ] 화면을 나눈 채로 시작이 막히는지 (쉬는 시간 뒤 "바로 집중 시작"도)
- [ ] 첫 화면에 티어 뱃지·이름·토큰·진행 막대가 나오는지
- [ ] 성공한 판이 끝나면 첫 화면 토큰이 목표 분만큼 오르는지
- [ ] 내 기록에 티어와 진행률이 나오는지
- [ ] 타이머를 시작하면 "지금 도전 중"에 뜨고, 끝나면 사라지는지
- [ ] 소리 스위치는 켜도 꺼도 소리를 내지 않는지 (들어보는 건 "미리 듣기")
- [ ] 소리를 끄면 울리던 소리가 바로 멈추는지
- [ ] (기기에서) 스위치를 연달아 눌러도 글자가 파랗게 선택되지 않는지
- [ ] 내 기록에 결과가 쌓이는지
- [ ] 게시판에 글이 올라가고 응원이 달리는지
- [ ] 순위표가 누적 시간 순인지, 이름 옆에 티어 뱃지가 붙는지
- [ ] 끝났을 때 소리가 나는지 (소리 스위치가 켜져 있을 때)
- [ ] **`?v=` 숫자를 올렸는지**

## 완성된 기능

1. 목표 시간 설정 및 타이머 실행 (슬라이더 1~120분, 빠른 선택 버튼)
2. 화면을 벗어나면 실패 처리 (Page Visibility API)
3. 개인 성공 기록 및 통계 — 기기가 달라도 닉네임이 같으면 따라온다
4. 공유 게시판 — 성공 기록 올리기, 이모지·응원 메시지
5. 순위표 — 성공 횟수 / 누적 시간 기준

그 밖에:

- **쉬었다 하기(뽀모도로)** — 목표 시간이 끝나면 5분 쉬고 다음 집중으로
  이어진다. 쉬는 동안에는 화면을 벗어나도 실패가 아니다
- **닉네임 + 숫자 4자리** — 같은 닉네임을 쓰려면 그 숫자를 맞혀야 한다
- 타이머가 도는 동안 화면이 꺼지지 않게 한다 (Screen Wake Lock)
- 인터넷이 끊겨도 타이머와 기록 저장은 그대로 되고, 연결되면 밀린 기록을 올린다
- 끝나면 소리로 알린다 (수업 중을 위해 끄는 스위치 있음)
- 화면을 벗어났을 때: **30초 안에 돌아오면 3번까지 봐주고, 그 밖에는 전부 실패.**
  봐주는 동안은 `endTime` 을 나가 있던 만큼 뒤로 밀어 **타이머를 멈춘다.**
  나가 있어도 시간이 안 줄기 때문에 오래 비워서 이득 볼 방법이 없다
  (오래 비운 쪽을 봐주면 "실패를 지우려고 일부러 안 돌아오는" 길이 열린다)
- 홈 화면에 추가하면 앱처럼 보인다 (`manifest.json`)
- 게시판에 새 글이나 내 글에 달린 응원이 있으면 빨간 점으로 알린다

무엇을 왜 바꿨는지는 [변경기록.md](변경기록.md) 에 정리해 두었다.

## 친구가 비밀번호(숫자 4자리)를 잊었을 때

앱 안에서는 바꿀 수 없다. 로그인이 없어서 "지금 바꾸려는 사람이 진짜
주인인지" 확인할 방법이 없기 때문이다. 바꾸는 기능을 넣으면 아무나 남의
숫자를 바꿔 닉네임을 빼앗을 수 있게 된다. (`users`는 누구나 읽을 수 있어서,
규칙으로 옛 비밀번호를 아는지 검사하는 것도 불가능하다.)

**대신 저장소 주인이 초기화해줄 수 있다.** Firebase 콘솔은 보안 규칙을
거치지 않기 때문이다.

1. Firebase 콘솔 → `Firestore Database` → `데이터` 탭
2. `users` 보관함에서 그 친구의 **닉네임과 같은 이름의 문서**를 찾는다
3. **⋮ → 삭제**
4. 그 친구가 앱에서 같은 닉네임으로 새 숫자를 정하면 된다

기록은 `records_v2`에 닉네임으로 저장되므로, 닉네임만 같으면
**예전 기록이 그대로 따라온다.**

## 알아두면 좋은 점

- **화면 자동 잠금**: iOS 16.4 이상이면 타이머 중 화면이 안 꺼진다.
  더 낮은 버전에서는 안내 문구가 대신 뜬다
- **비밀번호의 한계**: 숫자 4자리는 경우의 수가 1만 개뿐이라, 마음먹고
  뚫으려는 사람은 막지 못한다. 친구가 남의 닉네임을 무심코 쓰는 것을 막는
  용도다. 로그인이 없는 이상 여기까지가 한계다
- **친구가 쓴 글**은 반드시 `textContent`로 넣는다 (`innerHTML` 금지).
  HTML 태그를 적어도 그대로 글자로만 보이게 하기 위해서다
